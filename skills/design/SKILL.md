# Design workflow

[Português (Brasil)](SKILL.pt-BR.md)
Read the [Cursor adapter](../../references/cursor-adapter.md) for the available UI and UX workflow capabilities.

1. Inspect the repository, existing design system and user's constraints. Classify the work as adjustment, feature, or new product/redesign.
2. Adjustment: preserve existing direction and make the smallest justified change; record review evidence without requiring a full brief or alternative concepts.
3. Feature: use [design-brief](../design-brief/SKILL.md), reuse existing direction if justified, then [interaction-design](../interaction-design/SKILL.md) and [design-system](../design-system/SKILL.md).
4. New product/redesign: use design-brief, then [art-direction](../art-direction/SKILL.md), interaction-design and design-system.
5. Implement with [ui-build](../ui-build/SKILL.md).
6. Use [visual-review](../visual-review/SKILL.md) and [accessibility-review](../accessibility-review/SKILL.md); fix supported findings.
7. Deliver with [design-handoff](../design-handoff/SKILL.md).

Persist context using [workflow artifacts](../../templates/workflow.md) in docs/design/<slug>/ of the project. A file's existence is not approval. Record direction as proposed, approved, or delegated with its source. Ask one material question at a time; continue independent work. When the user delegates choices, decide and record delegation. Do not claim visual verification without observing the result. Reuse these artifacts after context compaction; check their revision before relying on old evidence.
