# Interaction design

[Português (Brasil)](SKILL.pt-BR.md)
Use the brief's primary job as the starting point. In flows.md record entry, action, feedback, success and recovery for the main flow.
Create a state matrix for loading, empty, error, success and disabled. Mark a state not applicable only with a reason; avoid inventing states a component cannot have.
For forms include labels, validation timing, error association, preserved input, submit feedback and retry. For data views include filters, no results, permissions and stale data when relevant.
Specify focus order and restoration for overlays, accessible action names, keyboard behavior, narrow-screen layout and content priority.
Use the same action vocabulary in buttons, progress and confirmation. Errors explain what happened and what to do; empty states give a useful next action.
Use actual product content or explicitly labeled samples. Do not claim user research or usability validation unless it occurred.
