# Design brief

[Português (Brasil)](SKILL.pt-BR.md)
Inspect product docs, routes, components, existing tokens and content before asking.
Write brief.md using the [artifact contract](../../templates/workflow.md):
product, audience, primary job, observable success, real content, constraints, references and open decisions.
Separate observed facts, user requirements and assumptions. Mark invented sample content as sample; do not invent business claims, testimonials or research.
If product, audience or job is unknown, propose a concrete interpretation and ask for confirmation unless the user has delegated that decision. Ask only what changes the outcome, one question at a time.
For an existing product, record the design system and constraints that must be preserved.
For a small adjustment, record only the task and existing context in review.md; do not force a full discovery exercise.
